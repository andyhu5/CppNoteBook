问题很清楚：`.run()` 要求闭包是 `FnMut`，意味着这个闭包可能被多次调用（每次收到 Windows service command 时调用一次），但 `move` 把 `log` 的所有权移进了闭包，第一次调用后 `log` 就被消耗掉了，第二次调用时它已经不存在了，编译器拒绝。

解决方案是用 `Arc<Mutex<>>` 包装 `log`，让闭包每次调用时都能安全地拿到 `log` 的引用，而不是消耗它的所有权：

```rust
use std::sync::{Arc, Mutex};
use std::thread;

let log = Arc::new(Mutex::new(log));

let result = windows_services::Service::new()
    .can_pause()
    .can_stop()
    .run(|_service, _command| {
        let log = Arc::clone(&log);   // 克隆 Arc，不克隆 log 本身

        let handler = thread::spawn(move || {
            // 线程拿到 Arc 的一份克隆，满足 Send + 'static
            let mut log = log.lock().unwrap();
            run_every_15_seconds(&mut *log);
        });

        if let Err(e) = handler.join() {
            eprintln!("Worker thread panicked: {e:?}");
        }
    });
```

`run_every_15_seconds` 签名改回借用形式：

```rust
fn run_every_15_seconds(log: &mut impl Write) {
    loop {
        if let Err(e) = write_current_time(log) {
            eprintln!("Write error: {e}");
            break;
        }
        thread::sleep(Duration::from_secs(15));
    }
}
```

------

## 为什么这样能解决问题

`Arc<Mutex<T>>` 把所有权问题和借用问题分开处理：

```
Arc   → 允许多个所有者共享同一份数据，克隆的是引用计数，不是数据本身
Mutex → 保证同一时刻只有一个线程能拿到内部数据的可变引用
```

闭包捕获的是 `Arc`，`Arc` 实现了 `Clone`，所以每次 `FnMut` 调用时执行 `Arc::clone(&log)` 只是增加引用计数，`log` 本身不被消耗，闭包可以被反复调用。`thread::spawn` 的闭包捕获的是 `Arc` 的一份克隆，`Arc<Mutex<T>>` 满足 `Send + 'static`，编译器放行。

不过有一点值得注意：如果 `.run()` 的闭包真的会被多次调用，而上一次调用 `spawn` 出来的线程还在运行（持有 `Mutex` 的锁），第二次调用时 `lock().unwrap()` 会阻塞在这里等锁释放。如果这不是期望的行为，可以改用 `try_lock()` 跳过本次调用：

```rust
let handler = thread::spawn(move || {
    if let Ok(mut log) = log.try_lock() {
        run_every_15_seconds(&mut *log);
    } else {
        eprintln!("Previous worker still running, skipping.");
    }
});
```
